# Sprint 4.1 — Implementation plan

- Design: [sprint.md](sprint.md). Section numbers (§) refer to it.
- Each part below is self-contained: an agent needs sprint.md and that part only. Parts run in
  order A, B, C1 … C7, D, E, F.
- Suggested grouping for implementers: **G1** = C1, C2 (keys and token validation: no database);
  **G2** = C4, C5 (administration API, audit, CLI); **G3** = C3 then C6, C7 (principals and caches,
  gateway and wiring, end to end); **G4** = part D (identity providers in containers, CI). After
  part A, G1, G2 and G4 do not depend on each other; G3 needs G1 for C3 and G2 for C7. T-602 to
  T-605 pass only once G3 is merged. A, B, E and F are one agent each. Because the risk class is

## Rules for the implementer

1. Branch `feat/4.1-trusted-token-issuers` from `main`; sign off every commit. One commit for A,
   one for B (tests, failing), one per step of C (message given with the step), one for D, one for E,
   one for F.
2. **One new Go dependency**: `github.com/go-jose/go-jose/v4` at the version of part A, imported
   by `internal/authn`, `internal/jwks` and `test/fakeidp` only, and only its root package. No other
   module is added to either `go.mod`. No version is typed by hand: `go get` writes it.
3. **No token, no key, no secret** in the repository: keys and tokens of tests are generated when
   the test runs; client secrets of the container tests are generated by `up.sh` under `local/`. No
   log line, error, audit row, usage row, span or CLI output holds a token, a segment of one, a JOSE
   header, a claim that was not verified, or the body of an issuer's document.
4. **The order of §5.4 is the contract.** `authn` has one function that validates a token, and its
   checks run in that order. Nothing of a token is logged, audited or cached before check 6
   succeeds. The JOSE library is always called with exactly one algorithm, the one of the header
   after it passed checks 2 and 4.
5. **The tenant comes from the registration or from the lookup function**, never from a header, a
   path, a body or an unlisted claim. The principal query runs inside `WithTenant` of that tenant.
6. **Only `internal/jwks` fetches issuer documents**, only through the transport function it is
   given, and only the gateway wires it. `internal/admin` imports neither `internal/jwks` nor
   `go-jose`.
7. Appendices A1 (migration 0008) and A2 (authentication queries) are copied byte for byte; both
   were run on PostgreSQL 16 while designing. If one does not work as written (for instance under
   `sqlc` or the schema lint), stop and ask.
8. Generated files are never edited by hand (`make generate`). SQL runs only as
   `queries.New(tx).<Method>` inside a `store` transaction helper (T-R10, T-R12).
9. Tests hold for root and non-root; nothing sleeps longer than 2 s; waiting is
   `testutil.Eventually`; time-dependent logic takes a clock. A bound is never made to pass by
   lengthening it and a database test never by skipping it. A test behind a build tag fails, never
   skips, when what its tag promises is missing.
10. CI actions are pinned to the commit hashes already in `ci.yml`; images are pinned by digests
    obtained with the commands of part D. A hash or digest is never typed from memory.
11. English everywhere; every exported identifier has a doc comment.

-- the tenant list of platform-level registrations, subject mappings, the directory that selects a

-- The tenant a claim value designates for a platform-level registration, or NULL. It takes one
-- registration and one value, returns one tenant ID, and cannot list.
CREATE FUNCTION pandokos.platform_issuer_tenant_lookup(p_issuer_id uuid, p_claim_value text) RETURNS uuid
    LANGUAGE sql STABLE SECURITY DEFINER
    SET search_path = pg_catalog, pg_temp
    RETURN (SELECT t.tenant_id FROM pandokos.platform_issuer_tenant t
             WHERE t.issuer_id = p_issuer_id AND t.claim_value = p_claim_value);

REVOKE ALL ON FUNCTION pandokos.platform_issuer_tenant_lookup(uuid, text) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION pandokos.platform_issuer_tenant_lookup(uuid, text) TO pandokos_gateway;

-- Which registration an issuer and audience pair selects (global table, no grant to any runtime
-- role). The primary key makes the pair unique across the installation, over both kinds of
-- registration. Maintained by the trigger below; read only through issuer_lookup.
CREATE TABLE pandokos.issuer_directory (
    issuer    text NOT NULL,
    audience  text NOT NULL,
    scope     text NOT NULL,
    tenant_id uuid,
    issuer_id uuid NOT NULL,
    CONSTRAINT issuer_directory_pkey PRIMARY KEY (issuer, audience),
    CONSTRAINT issuer_directory_issuer_id_key UNIQUE (issuer_id),
    CONSTRAINT issuer_directory_tenant_fkey FOREIGN KEY (tenant_id) REFERENCES pandokos.tenant (id),
    CONSTRAINT issuer_directory_scope_valid CHECK (scope IN ('tenant', 'platform')),
    CONSTRAINT issuer_directory_scope_tenant CHECK ((scope = 'tenant') = (tenant_id IS NOT NULL))
);

-- TG_ARGV[0]: 'tenant' (row of trusted_issuer) or 'platform' (row of platform_issuer).
CREATE FUNCTION pandokos.issuer_directory_sync() RETURNS trigger
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path = pg_catalog, pg_temp
AS $$
BEGIN
    IF TG_OP IN ('UPDATE', 'DELETE') THEN
        DELETE FROM pandokos.issuer_directory d WHERE d.issuer_id = OLD.id;
    END IF;
    IF TG_OP IN ('INSERT', 'UPDATE') THEN
        INSERT INTO pandokos.issuer_directory (issuer, audience, scope, tenant_id, issuer_id)
        VALUES (NEW.issuer, NEW.audience, TG_ARGV[0],
                CASE WHEN TG_ARGV[0] = 'tenant' THEN (pg_catalog.to_jsonb(NEW) ->> 'tenant_id')::uuid END, NEW.id);
    END IF;
    RETURN NULL;
END
$$;

CREATE TRIGGER trusted_issuer_directory AFTER INSERT OR UPDATE OR DELETE ON pandokos.trusted_issuer
    FOR EACH ROW EXECUTE FUNCTION pandokos.issuer_directory_sync('tenant');

-- The gateway records a refused token in the audit log of the tenant of the session, as
-- record_auth_failure does for a key (0005): one kind of row, fixed columns, no privilege on
-- audit_event for the gateway role. p_subject is empty unless the token's signature was verified.
CREATE FUNCTION pandokos.record_token_auth_failure(p_scope text, p_issuer_id uuid, p_reason text, p_subject text,
                                                   p_request_id text) RETURNS void
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path = pg_catalog, pg_temp
AS $$
BEGIN
    IF p_scope IS NULL OR p_scope NOT IN ('tenant', 'platform') OR p_issuer_id IS NULL
       OR p_reason IS NULL OR p_reason !~ '^[a-z_]{1,40}$'
       OR p_request_id IS NULL OR p_request_id !~ '^[0-9a-f]{32}$'
       OR p_subject IS NULL OR pg_catalog.char_length(p_subject) > 255 OR p_subject ~ '[[:cntrl:]]' THEN
        RAISE EXCEPTION 'invalid authentication failure record' USING ERRCODE = 'check_violation';
    END IF;
    INSERT INTO pandokos.audit_event (tenant_id, actor_type, action, resource_type, resource_id,
                                      outcome, request_id, detail)
    VALUES ((SELECT pandokos.current_tenant_id()), 'anonymous', 'auth.failure', 'token_issuer', p_issuer_id::text,
            'failure', p_request_id,
            pg_catalog.jsonb_strip_nulls(pg_catalog.jsonb_build_object(
                'reason', p_reason, 'listener', 'inference', 'issuer_scope', p_scope,
                'subject', NULLIF(p_subject, ''))));
END
$$;

### Appendix A2 — authentication queries, at the top of `internal/store/queries/sql/issuers.sql`

The file starts with a comment that says which statements run without a tenant session

       s.id AS service_account_id, s.name AS service_account_name, s.state AS service_account_state,
       s.valid_from, s.valid_until,
       t.id AS tenant_id, t.name AS tenant_name, t.state AS tenant_state,
       COALESCE((SELECT array_agg(r.role ORDER BY r.role) FROM pandokos.role_assignment r
                  WHERE r.service_account_id = m.service_account_id), '{}')::text[] AS roles

  JOIN pandokos.service_account s ON s.tenant_id = m.tenant_id AND s.id = m.service_account_id
  JOIN pandokos.tenant t ON t.id = m.tenant_id
 WHERE m.subject = sqlc.arg(subject)::text
   AND CASE WHEN sqlc.arg(scope)::text = 'tenant'
            THEN m.trusted_issuer_id = sqlc.arg(issuer_id)::uuid
                 AND EXISTS (SELECT 1 FROM pandokos.trusted_issuer i

                              WHERE l.issuer_id = m.platform_issuer_id AND l.tenant_id = m.tenant_id
                                AND l.claim_value = sqlc.arg(claim_value)::text)
                 AND EXISTS (SELECT 1 FROM pandokos.platform_issuer i
                              WHERE i.id = m.platform_issuer_id AND i.enabled)

  client timeout; each fetch runs under a context with `FetchTimeout` that covers discovery, key
  set and both bodies. Requests are `GET` with `Accept: application/json` and no other header.
  Bodies are read through `io.LimitReader(limit+1)`. The class is chosen per URL: discovery by the
  issuer's host, the key set by the host of `jwks_uri`. `http` URLs are refused before any request.
- `keys.go`: parse with `jose.JSONWebKeySet`; keep the usable keys of §5.4 check 5, at most 32,
  indexed by `kid`; a `kid` that appears twice is dropped entirely. `Key` applies the algorithm
  fit (type, curve, RSA size, the JWK's `alg`) at lookup, so one RSA key serves `RS*` and `PS*`.
- `jwks.go`: one entry per `Source` with a mutex, the keys, `fetchedAt`, `attemptedAt`, and a
  channel for the fetch in flight; the entries in a map bounded at 1024 with least-recently-used
  eviction. The fetch in flight is detached from the request's context (`context.WithoutCancel`
  plus the timeout): a caller that gives up does not cancel the fetch others wait for, and a
  waiting caller stops waiting when its own context ends, with `authz.ErrUnavailable`.
- State rules, exactly: no keys and no attempt within `MinRefetchInterval` → fetch and wait; no
  keys and a recent failed attempt → `ErrUnavailable` at once; keys older than `MaxStale` → drop
  them, then as "no keys"; keys older than `RefreshInterval` and no attempt within
  `MinRefetchInterval` → start a background fetch, answer from the keys; `kid` not found and no
  attempt within `MinRefetchInterval` → fetch, wait, look again; otherwise `ErrKeyNotFound`.
- Log: `issuer keys fetched` at `info` (source issuer, number of keys, duration) and `issuer keys
  not fetched` at `warn` with `class`; for `blocked`, the guard's reason as the existing code logs
  it. Never a URL's query, a body or a header.

**Verification:** `go test -race ./internal/jwks/...`; T-R36 for this package.

### C2. Token validation — `feat: validation of signed tokens against a registration`

**Files:** `internal/authn/token.go`. **Tests:** T-568 to T-573, the fuzz target.

```go
// registration is what validation needs of a row of trusted_issuer or platform_issuer.
type registration struct {
	Scope, ID      string    // "tenant" or "platform"
	TenantID       tenant.ID // zero for platform
	Issuer, Audience, JWKSURI string
	Algorithms     []string
	SubjectClaim, TenantClaim string
	RequiredClaims map[string]string
	Enabled        bool
}
// verified is what a valid token yields.
type verified struct{ Subject, TenantClaimValue string }

func looksLikeToken(presented string, maxBytes int) bool
func peek(presented string) (alg, kid, iss string, aud []string, err error)      // checks 1, 2 and the shapes of 3
func (a *Authenticator) validate(ctx context.Context, presented, alg, kid string, r registration) (verified, error) // checks 4 to 12
```

- `peek` decodes the first two segments with `base64.RawURLEncoding.Strict()` and a JSON decoder
  that refuses duplicate member names (decode into `map[string]json.RawMessage` after a token scan
  that fails on a repeated key at depth 1; do not rely on the library for this). It returns
  nothing else of the payload.
- `validate` calls `jose.ParseSignedCompact(presented, []jose.SignatureAlgorithm{alg})`, requires
  exactly one signature and no unprotected header, takes the key from `KeySource`, calls `Verify`,
  and reads claims **from the payload `Verify` returns**, never from `peek`'s. It then compares
  `iss` and `aud` again (check 7).
- Numbers are decoded with `json.Decoder.UseNumber` and converted with bounds (a value outside
  ±1e12 seconds is a failure of its check).
- Every failure is a `*Failure` with the reason of §5.4; `IssuerID`, `IssuerScope` and `TenantID`
  are set from the registration as soon as it is known, `Subject` only after check 11.
  `KeySource` errors that wrap `authz.ErrUnavailable` are returned as they are.

**Verification:** `go test -race ./internal/authn/ -run 'Token|Shape'`; `go test ./internal/authn/
-run xxx -fuzz FuzzParseToken -fuzztime 60s`; add the target to `make fuzz`.

### E3. Decision records (status `proposed`, date of the commit; index in `docs/adr/README.md`)

**0045. Trusted token issuers: registration, selection and validation** (refines 0005).
*Context*: 0005 fixed the two kinds of registration and the claims to validate; it left open
where registrations live, how a token finds its registration when tenants share an issuer, which
algorithms are accepted and what a token principal is. *Decision*: D-1 to D-7 and D-12 to D-16 of
the sprint, as numbered statements: (1) inference listener only; (2) shape decides key or token;
(3) two tables, tenant list with claim values, no wildcard; (4) one mandatory audience per
registration; (5) the pair issuer and audience is unique in the installation, a directory without
grants selects, ambiguity refuses; (6) ten asymmetric algorithms, allow-list before key lookup,
key fit; (7) the order of checks, `exp` required, skew, lifetime, signature on every request; (8)
exact subject mapping to a service account; the principal is that service account, with the
mapping as its key ID, `principal_kind` `token` in the ledger; (9) uniform 401, 503 when keys
cannot be obtained, failures audited when a tenant is known. *Consequences*: a shared issuer needs
a tenant-specific audience; a tenant learns that a pair is taken; one token cannot be revoked;
`sub` may be opaque, hence `subject_claim`. *Alternatives*: an installation-wide audience (cannot
tell tenants of a shared issuer apart); an audience assigned by Pandokos (excludes providers with
fixed audiences); the tenant chosen by the first mapping that matches (lets a tenant capture
another's workload); patterns for subjects; `principal_kind` `token` with the subject as
`principal_id` (reports would no longer group a service account's usage).

**0046. Retrieval and caching of issuer keys** (amends 0038 rule 7: "Credential validation, the
price download and the retrieval of issuer keys use the same transports"). *Context*: tenant
administrators supply URLs the gateway fetches; identity providers are often on private networks;
an outage must not stop calls, and a withdrawn key must stop being trusted. *Decision*: D-8 to
D-11: go-jose core for JWS and JWK; discovery or explicit `jwks_uri`; `https` always; public class
unless the operator lists the host; limits; lazy fetch, 15 min refresh, 10 s refetch bound, 6 h
staleness, then 503; cache headers not read; only the gateway fetches. *Consequences*: the bounds
of §5.6; a private issuer needs an operator's action; no feedback at registration time.
*Alternatives*: `go-oidc` (builds its own client and refetches without a bound we control); a
hand-written JWS verifier (no dependency, but signature code we would own); honouring cache
headers (lets the issuer set the withdrawal bound); a private flag per registration; fetching at
registration from the admin plane.

**0047. Identity providers in the test suite.** *Decision*: an in-process issuer with keys made
at run time for everything that needs faults or forged tokens; Keycloak and Ory Hydra in
containers, pinned by digest, behind the build tag `idp` in the root module (no third-party Go
module is needed, so ADR 0023 does not apply), one CI job; no key, token or client secret in the
repository. *Alternatives*: Dex (no client-credentials grant in v2.45.1), Zitadel (needs its own
database), recorded tokens (expire, and are secrets in fixtures).

History lines: 0005 (refined by 0045), 0018 (one module: go-jose v4, why, where it may be
imported), 0030 (a credential that does not start with `pdk_` may be a token), 0032 (`auth.failure`
